The idea in 30 seconds

Not an assistant.
An organization.

On its own, Claude Code is a great developer. DevTeam turns it into a team: every agent has a single responsibility, a model that fits the role and a protocol to communicate. They work in parallel thanks to Claude Code agent teams — a mailbox and a shared task list.

👤
You

Product owner

Describe what you want, approve the plan, decide. Commit, push, deploy and remote migrations always stay with you: the team prepares, you press the button.

The team

13 roles. Zero overlap.

Every role is a file in plugins/devteam/agents/ with prompt, model and tools. Opus where judgment matters (product, architecture, verification), Sonnet where execution speed matters. Click a card for details.

The flow · /devteam:feature

From request to commit,
in six steps.

Write one sentence. The team does the rest — but nothing starts without your go-ahead. Scroll and watch what happens in the terminal.

01

Understand and size

The lead reads the request and CLAUDE.md. If the job is small it tells you and does it alone — a team costs more tokens. If it's more an idea than a spec, product first writes a brief with acceptance criteria.

leadproduct
02

Design and contracts

architect explores the code, picks the simplest approach and writes the contracts: API, types, schema, env. Then it splits the work into tasks, each with an owner, files and acceptance criteria. Two tasks never own the same file.

architect
03

Your approval

The lead presents plan, team, tasks and risks. You can ask for changes, drop roles, switch models. Nothing starts without your go-ahead.

⏸ human gate — you decide
04

Parallel build

Teammates work at the same time and message each other with typed messages: [CONTRACT][QUESTION][BLOCKER][HANDOFF]. qa writes tests against the contracts while the others implement.

backenddatafrontendqa
05

Verification

Every implementation task passes the automatic gate (typecheck, lint, unit tests). Then qa gives a PASS/FAIL verdict mapped to the acceptance criteria, with evidence. security joins when auth, data, payments, LLMs or infra are touched.

qasecurity
06

Summary and proposed commit

What was done, which files, which commands were run, open points and a ready commit message. The team shuts down. Commit, push, deploy and remote migrations stay with you.

Installation

Ready in three steps.

The repo is public: no credentials needed. Once per machine, once per project, then you work.

01
in Claude Code

Add the marketplace and install

Register the espertini-devteam marketplace and install the plugin.

/plugin marketplace add iamdex/devteam /plugin install devteam@espertini-devteam
02
once per machine

Setup and restart

Enables agent teams (experimental, off by default), picks the display mode and proposes safe permissions. Then restart Claude Code.

/devteam:setup # → restart Claude Code
03
once per project

Onboard the repo

Analyzes stack, commands and conventions. Writes the ## DevTeam section in CLAUDE.md and .claude/devteam.json. Review them and commit them.

/devteam:onboard # → review and commit the 2 files
Requirements: Claude Code ≥ 2.1.32 (tested 2.1.325) jq or python3 for the hooks tmux — only for split panes
Why is setup needed? A plugin can't set environment variables by itself. /devteam:setup adds CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 to your ~/.claude/settings.json, showing every change as a diff before writing it. Prefer a local folder? /plugin marketplace add /path/to/devteam

Quality gates and guardrails

Free to work.
Not free to destroy.

Three hooks run under every session. They're not suggestions in a prompt: they're scripts that actually block.

📋
TaskCreated

Every task has an owner

Inside a team, every task must have Owner:, Files: and Acceptance: in its description (review/plan/research only Owner:). That's what keeps two agents off the same file.

✅
TaskCompleted

No "done" until it's green

Before an implementation task is closed, it runs the checks in .claude/devteam.json. If they fail, the task stays open and the agent receives the error output.

🛡️
PreToolUse · Bash

Irreversible commands go through you

Blocks anything that destroys work or touches production and asks to go through you. Disable it per project with "guard": false or per session with DEVTEAM_GUARD=0.

RECOMMENDED

Remote Control

Full team. Claude Code runs on a machine of yours, the tablet is just the window.

🖥 server / Mac📱 Claude app
  1. On the machine: Claude Code ≥ 2.1.51, then the plugin and /devteam:setup.
  2. Clone the project and run /devteam:onboard the first time.
  3. Start inside tmux so the session survives:
    tmux new -s devteam claude --remote-control
    From an open session: /remote-control or /rc.
  4. On the tablet: Claude app → Code → pick the session. Run /devteam:feature and approve from there.
  • agent teams, hooks and guardrails just like local
  • all 7 commands

Cloud sessions

Subagents, no team. They run on Anthropic's infrastructure, no machine of yours.

☁️ Anthropic cloud🌐 browser / app
  1. Declare the plugin in the project's .claude/settings.json (committed) — see the settings.json tab.
  2. Open the cloud session on the repo: the plugin loads by itself.
  3. Use the commands that adapt to subagents.
  • review, debug, strategy, release adapt by themselves
  • every agent usable as a subagent
  • agent teams not available in the cloud
  • /devteam:feature needs Remote Control or local
Costs and limits

Honest about what it costs
and what it doesn't do.

How many teammates?

Every teammate is a full Claude session: tokens grow with the number of agents. Drag and see.

4
🧪

Experimental

/resume doesn't restore in-process teammates, task status sometimes lags, one team per session.

💬

Interactive only

Agent teams only work in interactive sessions, not with claude -p or the Agent SDK. An autonomous team on a server is a different architecture (v2).

🎯

On-demand roles

The lead only activates those with a task. growth joins features only when there's a commercial side (copy, pricing, stores).

🙈

No shared memory

Teammates don't see the lead's conversation: that's why the lead writes complete briefs and stable context lives in CLAUDE.md.

🪆

No teams within teams

Teammates can't create other teammates. The hierarchy is flat: one lead, N specialists.

🏷️

Named subagents

While agent teams are on, subagents that Claude gives a name start as teammates. To get plain subagents back in a project: set the variable to "0" in .claude/settings.local.json.

FAQ

Frequently asked questions

Do I have to use all 13 agents every time?

No, by design. The lead only activates the roles that have a task — usually 3–5. For a small job it tells you and does it alone, because a team costs more tokens than a single session.

How do I change a role's model?

Edit model: in the frontmatter of the file in plugins/devteam/agents/, or ask the lead for a specific model when it launches the team ("use Opus for backend too").

The gate blocks every task, what's going on?

The project is probably "red" to begin with: typecheck, lint or tests already fail before the team touches anything. Fix it first, or temporarily set "gateTasks": false in .claude/devteam.json. Only put fast, reliable checks in the gate: qa runs the e2e tests.

Can I talk to a teammate directly?

Yes. In in-process mode: ↑/↓ to select it in the agents panel, Enter to open it, Ctrl+T for the task list. In auto mode inside tmux or iTerm2 every teammate gets its own pane.

Can the team push or deploy by itself?

No. The guardrail blocks force pushes, destructive resets, supabase db push, ssh/scp/rsync, npm publish, eas submit, fastlane and the like. The team prepares everything — proposed commit, submission checklist — and you execute.

Does it work with my stack?

The team is generic: it reads your CLAUDE.md and follows the conventions it finds. It also ships knowledge skills for TypeScript, .NET, Supabase, React/Next.js, Expo, SwiftUI, voice agents and Docker/Dokploy. For anything else, add a stack-<name> skill.

Why do some roles use Opus and others Sonnet?

Opus where judgment matters: deciding what to build (product, growth), how to build it (architect) and whether it's really right (qa, security). Sonnet where what matters is executing a clear plan with defined contracts, well and fast.
