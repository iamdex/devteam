Non un assistente.
Un'organizzazione.

Claude Code da solo è un ottimo sviluppatore. DevTeam lo trasforma in un team: ogni agente ha una sola responsabilità, un modello adatto al ruolo e un protocollo per comunicare. Lavorano in parallelo grazie agli agent teams di Claude Code — una mailbox e una task list condivisa.

Il team

13 ruoli. Zero sovrapposizioni.

Ogni ruolo è un file in plugins/devteam/agents/ con prompt, modello e strumenti. Opus dove serve giudizio (prodotto, architettura, verifica), Sonnet dove serve velocità di esecuzione. Clicca una card per i dettagli.

Capire e dimensionare

Il lead legge la richiesta e il CLAUDE.md. Se il lavoro è piccolo te lo dice e lo fa da solo — un team costa più token. Se è più un'idea che una specifica, product scrive prima un brief con criteri di accettazione.

architect
03

La tua approvazione

Il lead ti presenta piano, team, task e rischi. Puoi chiedere modifiche, togliere ruoli, cambiare modello. Non parte niente senza il tuo ok.

04

Build in parallelo

I teammate lavorano contemporaneamente e si scrivono con messaggi tipizzati: [CONTRACT][QUESTION][BLOCKER][HANDOFF]. qa scrive i test sui contratti mentre gli altri implementano.

Verifica

Ogni task di implementazione passa il gate automatico (typecheck, lint, unit test). Poi qa dà un verdetto PASS/FAIL mappato sui criteri di accettazione, con evidenze. security entra se si toccano auth, dati, pagamenti, LLM o infra.

Comandi

Sette comandi.

Installazione

Pronto in tre passi.

Il repo è pubblico: non servono credenziali. Una volta per macchina, una volta per progetto, poi lavori.

01
in Claude Code

Aggiungi il marketplace e installa

Registra il marketplace espertini-devteam e installa il plugin.

/plugin marketplace add iamdex/devteam /plugin install devteam@espertini-devteam
02
una volta per macchina

Setup e riavvio

Abilita gli agent teams (sperimentali, spenti di default), sceglie il display mode e propone permessi sicuri. Poi riavvia Claude Code.

/devteam:setup # → riavvia Claude Code
03
una volta per progetto

Onboard del repo

Analizza stack, comandi e convenzioni. Scrive la sezione ## DevTeam in CLAUDE.md e .claude/devteam.json. Controllali e committali.

/devteam:onboard # → rivedi e committa i 2 file
Requisiti: Claude Code ≥ 2.1.32 (testato 2.1.325) jq oppure python3 per gli hook tmux — solo per i pannelli separati
Perché serve il setup? Un plugin non può impostare variabili d'ambiente da solo. /devteam:setup aggiunge CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 al tuo ~/.claude/settings.json, mostrandoti ogni modifica come diff prima di scriverla. Preferisci una cartella locale? /plugin marketplace add /percorso/devteam

Gate di qualità e guardrail

Libertà di lavorare.
Nessuna libertà di distruggere.

Tre hook girano sotto ogni sessione. Non sono suggerimenti nel prompt: sono script che bloccano davvero.

📋
TaskCreated

Ogni task ha un padrone

Dentro un team, ogni task deve avere Owner:, Files: e Acceptance: nella descrizione (review/plan/research solo Owner:). È ciò che evita due agenti sullo stesso file.

✅
TaskCompleted

Niente "fatto" finché non è verde

Prima di chiudere un task di implementazione esegue i checks di .claude/devteam.json. Se falliscono, il task resta aperto e l'agente riceve l'output dell'errore.

🛡️
PreToolUse · Bash

I comandi irreversibili passano da te

Blocca ciò che distrugge lavoro o tocca la produzione e chiede di passare da te. Si disattiva per progetto con "guard": false o per sessione con DEVTEAM_GUARD=0.

Remote Control

Team completo. Claude Code gira su una macchina tua, il tablet è solo la finestra.

🖥 server / Mac📱 app Claude
  1. Sulla macchina: Claude Code ≥ 2.1.51, poi plugin e /devteam:setup.
  2. Clona il progetto e lancia /devteam:onboard la prima volta.
  3. Avvia dentro tmux così la sessione sopravvive:
    tmux new -s devteam claude --remote-control
    Da una sessione aperta: /remote-control o /rc.
  4. Sul tablet: app Claude → Code → scegli la sessione. Lancia /devteam:feature e approva da lì.

Sessioni cloud

Subagent, senza team. Girano sull'infrastruttura Anthropic, nessuna macchina tua.

☁️ cloud Anthropic🌐 browser / app

  2. Apri la sessione cloud sul repo: il plugin si carica da solo.
  3. Usa i comandi che si adattano ai subagent.

Quanti teammate?

Ogni teammate è una sessione Claude completa: i token crescono con il numero di agenti. Trascina e guarda.

4
🧪

Sperimentale

/resume non ripristina i teammate in-process, lo stato dei task a volte resta indietro, un solo team per sessione.

💬

Solo interattivo

Gli agent teams funzionano solo in sessioni interattive, non con claude -p o Agent SDK. Un team autonomo sul server è un'altra architettura (v2).

🎯

Ruoli on-demand

Il lead attiva solo chi ha un task. growth entra nelle feature solo se c'è un lato commerciale (copy, pricing, store).

🙈

Niente memoria condivisa

I teammate non vedono la conversazione del lead: per questo il lead scrive brief completi e il contesto stabile sta in CLAUDE.md.

🪆

Niente team nei team

I teammate non possono creare altri teammate. La gerarchia è piatta: un lead, N specialisti.

🏷️

Subagent con nome

Mentre gli agent teams sono attivi, i subagent a cui Claude dà un nome partono come teammate. Per tornare ai subagent in un progetto: variabile a "0" in .claude/settings.local.json.

FAQ

Domande frequenti

Devo usare tutti e 13 gli agenti ogni volta?

No, ed è voluto. Il lead attiva solo i ruoli che hanno un task — di solito 3–5. Per un lavoro piccolo te lo dice e lo fa da solo, perché un team costa più token di una sessione singola.

Come cambio il modello di un ruolo?

Modifica model: nel frontmatter del file in plugins/devteam/agents/, oppure chiedi al lead un modello specifico quando lancia il team ("usa Opus anche per backend").

Il gate blocca ogni task, cosa succede?

Probabilmente il progetto è "rosso" in partenza: typecheck, lint o test falliscono già prima che il team tocchi qualcosa. Sistemalo prima, oppure metti temporaneamente "gateTasks": false in .claude/devteam.json. Nel gate metti solo controlli veloci e affidabili: gli e2e li lancia qa.

Posso parlare direttamente con un teammate?

Sì. In modalità in-process: ↑/↓ per selezionarlo nel pannello agenti, Invio per aprirlo, Ctrl+T per la task list. In modalità auto dentro tmux o iTerm2 ogni teammate ha il suo pannello.

Il team può fare push o deploy da solo?

No. Il guardrail blocca force push, reset distruttivi, supabase db push, ssh/scp/rsync, npm publish, eas submit, fastlane e simili. Il team prepara tutto — commit proposto, checklist di invio — e tu esegui.

Funziona con il mio stack?

Il team è generico: legge il tuo CLAUDE.md e segue le convenzioni che trova. In più ha skill di conoscenza pronte per TypeScript, .NET, Supabase, React/Next.js, Expo, SwiftUI, voice agent e Docker/Dokploy. Per altro, aggiungi una skill stack-<nome>.

Perché alcuni ruoli usano Opus e altri Sonnet?

Opus dove conta il giudizio: decidere cosa costruire (product, growth), come costruirlo (architect) e se è davvero giusto (qa, security). Sonnet dove conta eseguire bene e in fretta un piano già chiaro, con contratti definiti.
